# CAC Art Lab online collector

The public website saves each choice before the next pair is shown. The Worker retains the original 60-pair `/choices` endpoint and the v7 `/experience/choices` endpoint. Both use the existing D1 binding `DB`, the site-only `ALLOWED_ORIGIN`, and a server-side test-session registry. The v7 endpoint accepts A, B or skip, validates the pair against `experience_manifest.json`, and writes to a separate `experience_choices` table. New v7 events also store the two-letter country code from Cloudflare's `request.cf.country`, or unknown when it is unavailable; the browser cannot supply this field. Repeating an identical event ID and payload returns a duplicate acknowledgment without another row. A conflicting event or another choice for the same round position is rejected.

## Deployment order

1. Back up the production D1 database and confirm the current v7 site and collector are healthy.
2. Apply `migrate_experience_country.sql` once to the existing D1 database. It adds a nullable column and an index to `experience_choices`; existing rows stay unknown and the legacy `choices` table is unchanged. New installations use `schema.sql` and do not need this migration.
3. Publish the updated static site from `web/` and confirm the country notice appears before choices. Existing saving remains available; country collection has not started.
4. Deploy the Worker with the existing `ADMIN_TOKEN`, `ALLOWED_ORIGIN=https://vincentliu.ai`, and D1 binding. `/health` still reports the 60-pair version; `/experience/health` still reports `cac-met-paintings-v7`.
5. Register a fresh test session through `POST /admin/test-sessions`, then send one v7 choice from the website test flow. Check `GET /admin/experience-countries?environment=test` and `GET /admin/experience.csv?environment=test`; the CSV country must match D1. Remove only that registered session through `DELETE /admin/test-sessions/<session-id>`. Verify the public site and collector remain healthy. Do not erase production records.

The Wrangler template preserves the existing production settings for disabled preview URLs and enabled observability logs. Check dashboard settings before subsequent deployments because Wrangler applies local configuration to the remote Worker.

Admin routes require `Authorization: Bearer <ADMIN_TOKEN>`. `node worker/owner_cli.mjs countries` shows production country totals, including skips, and `countries-test` shows the test partition. The private `/admin/experience-countries` route reports choice and anonymous-session counts per country; sessions are not verified people. Default CSV export is production; `environment=test` selects only registered test sessions and the CSV includes `country_code` for each v7 event. The public `/experience/community?pairs=id1,id2` endpoint reports only production A/B counts for up to ten known v7 pairs; skips, test records, and country codes are excluded. No browser credential, IP value, or client-supplied country is accepted as part of an event. The app database does not store raw IP addresses or precise location, although Cloudflare may process IP addresses in service logs. Country codes can be missing or inaccurate due to VPNs and proxies; older rows have no country information.

The CSV endpoint currently reads the matching v7 rows in one request. Before large-scale recruitment, replace it with the separately prepared paginated exporter and validate Cloudflare D1 behavior and capacity. The local million-choice work is not part of this deployment.
